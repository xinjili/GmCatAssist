# 光猫快连 · GmCatAssist

> 给宽带装维用的安卓小工具：**拍一张光猫背面的标签 → 自动认出 WiFi 信息 → 优先连 5G → 一键打开光猫后台**。

装宽带时需要连上光猫的 WiFi 才能进 `192.168.1.1` 做注册开通。光猫背面贴纸上印着 SSID、WiFi 密码、后台地址/账号/密码、SN、MAC，字小、有反光、还常常带油污，站在梯子上手抄一遍很费劲，抄错一位就连不上、白跑一趟。这个 App 就是为了省掉这一遍手抄。

---

## 功能

**拍照识别**
调用视觉大模型读光猫标签贴纸，直接返回结构化字段，而不是一整段文字：

- 无线名称 / WiFi 密码，**2.4G 与 5G 分开两组**
- 后台地址 / 后台账号 / 后台密码
- **SN**（华为光猫支持 `HWTC` 与 `48575443` 两种印法）、MAC、设备型号
- 其他标签信息（PON SN、生产日期等）

**5G 优先**
标签上通常只印一组 SSID 和密码，5G 靠 `-5G` 后缀区分、密码相同。由此推导出两个频段的独立信息后：

1. 拍完照扫一次周边，给两个频段标注「已扫到 / 未检测到」
2. 默认选中 5G
3. **扫描结果只做参考，不据此自动切换频段** —— 部分机型扫描列表不完整，自动切换会把本来能连上的网络换掉
4. 点卡片右上角的标注，可以打开附近 WiFi 列表（按信号排序），点选即填入 SSID，无需重拍

**接近一键的连接**
用 Android 的 `Settings.ACTION_WIFI_ADD_NETWORKS` + `WifiNetworkSuggestion` 调起系统「添加网络」弹窗，**SSID 和密码都已预填**，用户点一下即可写入系统 WiFi。

**打开后台**
唤起系统浏览器访问光猫后台地址。不内嵌 WebView —— 注册过程中可能要切页面、看工单，浏览器多标签更顺手，而且浏览器自带密码记忆。

**默认超级密码参考**
识别结果最底部会列出移动 / 联通 / 电信三家光猫的出厂默认超级管理员账号密码，每项都能单独复制。

**但要提醒**：这些是出厂值，多数光猫已经被运营商通过 TR-069 远程改成动态密码了，登录失败是常态，直接打客服要（电信 10000 / 移动 10086 / 联通 10010）。这个表的价值是「先试一下，省得每次都问」，不是「一定能登进去」。

**测试网速**
同样的方式唤起浏览器，打开设置里配置的测速页（可填运营商自己的测速平台）。点之前会提示当前连的是哪张网，避免把手机流量的速度当成宽带速度。

## 关键设计取舍

这个项目里几个不那么显然的决定，以及背后的原因。

### 为什么是独立 App，而不是小程序

Android 10 起 Google 出于安全考虑，移除了第三方应用直接改写系统 WiFi 配置的能力。微信小程序的 `wx.connectWifi` 在 Android 10+ 上只能让**小程序自身**使用该网络，用户切出去依然没网；iOS 上反而可以真正改写系统设置。

所以小程序方案在 Android 上是残废的（只能生成二维码或复制密码），而装维现场主要用安卓。走原生 App 才能用上系统的「添加网络」弹窗。

### 为什么识别必须在连接之前

光猫未开通业务时，连上它的 WiFi 只有内网、没有外网。这意味着**识别请求必须在连接之前完成**，此时手机还在走 4G/5G 流量。这个顺序是硬性的，不能反过来。

连上之后 App 会明确告知「没有外网是正常的」，不会让人对着加载不动怀疑人生。

### 为什么不提取 LOID

LOID / 逻辑 ID 和宽带认证密码**不在光猫标签上**，它们在运营商的装维系统里。

早期版本试过让模型提取 LOID，结果适得其反：标签上没有真实数据时，视觉模型会把 SN 或别的编号硬塞进去，产生一个看起来很像但完全错误的凭据。相比不提取，这种幻觉更有害。

所以识别范围严格限定在标签上确实印着的东西。App 能提供的注册相关硬信息，只有 SN —— 而这恰好是最难手抄、又必填的那一个。

### 关于识别速度

三条都是踩过才知道的：

**1. 关掉思考模式**

DeepSeek 系列的 thinking 默认开启，effort 默认 high。识标签是纯粹的字段抄写，不需要推理，思维链纯属白烧时间。请求体里显式加 `"thinking": {"type": "disabled"}`。

注意别顺手塞 `reasoning_effort: "none"` —— 那个字段只接受 low/high/max，传 none 可能直接 400。

**2. 图片分辨率不影响推理开销**

服务端会把图片自动缩放到约 1300×1300、每张上限 1024 token。所以传 1800px 和 1280px 的推理代价完全相同，压缩只对上传流量有意义，对速度影响很小。

真正影响识别率的是**标签在画面里占多大**。同样是 1600px，标签占 80% 和占 40%，字高差一倍。所以界面上引导的是「把标签拍满画面」，而不是靠提高分辨率硬扛。

**3. EXIF 方向必须矫正**

相机竖拍时像素常常是横的，方向只写在 EXIF 里。不矫正的话模型看到的是躺倒的标签，既慢又容易认错。

### 为什么能应对各种型号的光猫

现场会遇到华为、中兴、烽火、吉比特、天邑、创维、九联、华勤、诺基亚贝尔等不同品牌，再叠加移动 / 电信 / 联通三家定制，标签的字段名、排版方向、中英文、有无条形码、是否表格化全都不一样。

所以提示词刻意**不写「在已知字段名里找目标」**，而是描述每类信息的**含义**，让模型按语义判断：

- 不是「找『WLAN名称』这个字段」，而是「找表示无线网络名称的信息，可能写作 WLAN名称 / SSID / WiFi名称 / 无线网络标识 / 默认无线网络名称 等」
- 不是「找『WLAN密码』」，而是「找表示无线密码的信息，可能写作 WLAN密码 / 无线网络密钥 / WPA密钥 / 预共享密钥 等」

穷举字段名只能覆盖见过的型号，按含义描述才能覆盖没见过的。

另外单独处理了**双频合一**：有些设备只印一个无线名称，2.4G 和 5G 共用同一个 SSID。这种情况下模型会返回 `has_separate_5g: false`，App 直接把 5G 卡片隐藏，而不是硬拼一个 `-5G` 后缀，造出一个根本不存在的网络让你去连。

### 为什么扫描结果只做参考

Android 13 起扫描周边 WiFi 由 `NEARBY_WIFI_DEVICES` 控制，但多数定制 ROM（尤其 MIUI / HyperOS）仍会限制返回内容：SSID 可能被脱敏、列表可能不完整、`startScan` 受节流后返回旧缓存。

实测中出现过这样的情况：**SSID 与光猫真实名称完全一致、密码正确、连接一次成功，但扫描列表里就是没有这个网络**。

既然「系统添加网络弹窗」根本不依赖扫描结果（它只需要 SSID 和密码两个字符串），扫描就只能当参考，不能充当连接的前置条件，更不能拿它去替用户更换频段。所以这个 App 的标注措辞是「已扫到 / 未检测到」，而不是「有 / 没有」。

### 为什么自动填充只做前几次

后台登录页各厂商结构不同，脚本注入本身就靠通用启发式（找第一个 text 输入框和 first password 输入框）。如果每次页面跳转都重新注入，登录成功后翻到「修改密码」页就会被误填。所以自动填充有次数上限，且不做自动提交（避免连续失败触发账户锁定）。

## 技术栈

- **Java**，纯原生 SDK，**零第三方依赖**
- minSdk 29（Android 10）/ targetSdk 34
- 视觉识别走 OpenAI 兼容接口（`/chat/completions` + `image_url`），火山方舟、通义、智谱、DeepSeek 等均可
- 构建产物 APK 约 **68 KB**

零依赖不是洁癖，是为了构建稳定 —— 不需要下载任何 AndroidX / 图片库 / 网络库，`gradle assembleRelease` 十几秒出包。

## 构建

需要 JDK 17、Android SDK（platform 34）、Gradle 8.2+。

```bash
# 配置 SDK 路径
echo "sdk.dir=/path/to/Android/Sdk" > local.properties

gradle assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

首次构建需联网解析 Android Gradle Plugin 依赖，之后可离线。

## 使用

1. 安装 APK，打开 App
2. 右上角「设置」，填三项：接口 Base URL、API Key、视觉模型名；下方还可以填**测速页地址**（默认 speedtest.cn，可换成运营商自己的测速平台）
3. 对着光猫背面标签拍照
4. 核对识别结果（字段都能直接改），点对应卡片里的「连接 5G / 连接 2.4G」
5. 系统弹窗里点「连接」
6. 点「进后台」打开 `192.168.1.1`

**权限说明**

扫描周边 WiFi 会申请两个权限：`NEARBY_WIFI_DEVICES`（Android 13+ 的新权限）与 `ACCESS_FINE_LOCATION`（传统路径）。**任一授予即可**。

两个都要是因为实测中 MIUI / HyperOS 上常见「新权限看起来已授予，但 `getScanResults()` 返回空列表」，而传统的定位路径反而正常。应用不采集、不上传任何位置信息，这个权限只用于读取 WiFi 列表。

- **Android 12 及以下**：还需要打开系统「位置信息」开关，否则扫描结果恒为空
- **扫描失败不影响连接**：系统「添加网络」弹窗只要 SSID 和密码，不看扫描结果

如果两个频段右上角显示「扫描不可用」，说明没拿到周边 WiFi 列表（权限被拒、WiFi 未开或系统限制）。此时应用**不会**自动切换频段，仍按你点的那个连接 —— 因为「没扫到」和「确实不存在」是两回事，不能混为一谈。

## 隐私

- **不收集任何数据**，无统计、无上报
- 识别图片会发送到你自己配置的模型接口，识别完成后本地临时文件立即删除，不进相册
- API Key 只存在本机 SharedPreferences
- 不保存任何光猫信息，退出即清空

## 已知限制

- 依赖视觉模型的识别质量，标签严重破损、油污、强反光时仍可能认错。App 会针对可疑结果给出提示（密码位数异常、混入全角字符、附近扫不到该 SSID 等），但最终仍需人工核对
- 系统「添加网络」弹窗在少数深度定制 ROM 上可能不出现，此时会降级为「复制密码 + 跳转 WiFi 设置」
- 周边 WiFi 扫描在 Android 13+ 与定制 ROM 上可能返回不完整列表（SSID 脱敏、系统节流等），此时标注显示「未检测到」或「未检测」。**这只是参考信息，不影响连接** —— 系统「添加网络」弹窗并不依赖扫描结果，实测中常见「未检测到但能正常连上」
- 未做多语言，界面仅中文
